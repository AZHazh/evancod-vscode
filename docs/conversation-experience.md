# 对话执行体验

对话按“进展说明 → 工具活动组 → 下一段说明 → 最终答复”展示。助手正文使用文档布局；连续工具默认折叠，标题显示数量、工具类别及执行状态，展开后可查看原有命令、Diff、结果和 Agent 卡片。Thinking 独立保留，默认折叠，完成后计时固定。

本轮产生最终答复后，之前的进展说明、Thinking、工具组、上下文压缩及已处理的交互记录自动收进一个默认折叠的“用时 …”区域。展开后按原顺序查看，工具组和 Thinking 仍可独立展开；最终答复与生成图片保留在外面。耗时从本轮用户消息到最终答复结束计算，历史恢复时使用已保存的时间，结束后不再增长。没有过程记录的直接答复不创建空折叠区。

用户消息和过程正文不再展示底部复制、时间；仅最终答复保留复制按钮。等待回答的 Ask、待审批计划和仍在执行的轮次继续直接展示；中断或停止的内容不会被视为成功答复收起。兼容没有阶段字段的旧会话：仅在轮次已结束时，将末尾无状态的正文作为历史答复，显示层推断不回写原始记录。

工具权限请求保留在会话记录中，展示位置改为输入框上方的紧凑授权栏。默认仅显示操作摘要、详情入口和授权按钮，去掉重复标题、状态徽章和终端装饰；窄侧栏自动分为两行。命令、Diff、说明及原始参数默认收起，展开后的详情限高滚动，按钮始终可见。区域参与页面布局，不覆盖消息。多个请求按时间顺序处理，剩余数量在摘要旁显示，保留允许一次、本次会话允许及拒绝的原有语义。切换会话时显示对应会话的待授权队列，新请求的详情默认收起；停止、取消及超时后请求失效。

Task 面板与授权卡片在输入框上方共享同一布局区域，授权靠右浮在任务面板前面，两者同时存在时高度取较大者，不再上下叠加；授权退出后任务面板保持原来的展开状态。Ask 问答继续保留，计划审批仍显示在原来的对话位置。正文、Thinking、Ask、计划审批和图片都是工具分组边界。分组只影响展示，不合并或删减底层工具记录。

## 样式与内容预览

授权卡片保留橙色“允许一次”、描边“本次会话允许”和红色“拒绝”的按钮配色。卡片按内容收窄并靠右排列，常规宽度为 308–420px，窄侧栏自动缩小；使用 18px 圆角、半透明渐变、背景模糊、柔和高光和多层阴影，恢复文件更新、写入、删除与命令等操作图标。提示改为“准备更新文件”等自然描述，下面保留具体路径或命令，完整参数和 Diff 仍可展开。

授权提示从右侧淡入；选择后立即向扩展发送原有权限响应，同时淡出卡片。多个请求按顺序完成退出和进入动画，退出中的卡片使用 `inert` 禁用交互，避免重复点击。系统偏好减少动态效果时去掉位移与模糊，缩短过渡。工具标题的图标、名称、状态与展开箭头居中对齐；暗色主题的对话正文使用白色，浅色主题保持深色正文，元信息继续使用次级颜色。

结束后的“已思考”使用与工具记录一致的透明折叠行：思考图标、标题与右侧箭头，不再使用胶囊底色；默认收起，展开后显示左侧细线缩进的内容。“思考中…”保留原来的胶囊样式、耗时和 token 提示，支持键盘切换及展开状态恢复。

文件链接参考本机安装的 Codex VS Code 扩展的打开流程：先解析路径和行列号，绝对路径直接打开，相对路径按会话工作目录和工作区解析。支持 Windows 盘符、`file://`、URI 编码、空格、`:行:列`、`#L行C列` 及范围。Markdown 链接保留完整目标，显示标题可以使用短文件名。系统提示要求所有模型引用工具确认过的绝对路径，使链接直接定位到指定文件和行号。

路径解析不弹文件选择框，也不截短缺失的绝对路径去打开别的同名文件。旧相对引用仅在完整路径后缀唯一匹配时恢复；无法唯一定位或目标不存在时显示失败原因。文件在主编辑区打开并固定标签，行列号越界时由 VS Code 校正。目录引用在 Explorer 中显示。

粘贴超过 2000 字符或达到 20 行的文本时，卡片显示在编辑区上方，与图片共用附件区；卡片包含文本图标、首行预览、“粘贴的文本”说明和移除按钮。点击卡片可将原文放回文本框继续编辑，移除附件不影响输入正文，清空输入正文也不移除附件。支持多份文本与图片同时附加，发送时按卡片顺序拼接完整原文，再以空行分隔输入正文，文件与技能仍保留在正文中的顺序。

发送后长文本使用胶囊预览，旧历史中的长文本也使用相同展示。点击胶囊通过 `evancod-text` 只读文档在 VS Code 主编辑区查看完整内容，同一内容重复打开复用标签，不向工作区写临时文件。复制、模型请求和会话恢复都使用完整原文，卡片标题仅用于显示。

## 多模型适配

当前实现使用现有 Anthropic、OpenAI Chat 和 OpenAI Responses 客户端及工具执行循环，无需模型输出特殊 JSON 或原生 `commentary` / `final_answer` 字段。

- 通用系统提示要求模型在执行前简述行动，在取得进展或改变方向时更新说明，最终答复报告真实结果。
- 扩展端为每段正文分配稳定 `itemId`，实时事件与持久化记录共用标识。工具调用结束当前进展段；只有引擎明确发出 `message_complete.completed = true`，当前正文才转为最终答复。
- 停止、上游错误、输出截断和执行上限均保留中断状态，不会将已有正文提升为成功的最终答复。工具结束也不会等同于整个任务完成。
- 模型省略进展文字时，界面依照实际工具事件显示“正在读取文件”“正在执行命令”等状态，不推测发现或生成虚构总结。说明的质量、频率及工具调用可靠性仍取决于模型能力。
- 没有 Thinking 的模型不显示思考块；旧会话没有新增字段也能继续显示。旧事件没有 `itemId` 时保留兼容处理。扩展重启后，遗留流式块及待授权请求按中断处理。

## 验证

- `npm run compile`：扩展类型检查与编译。
- `npm run test:unit`：含消息标识、分段、丢弃临时答复、会话隔离和中断恢复的回归测试。
- `npm --prefix webview test`：前端 Store 和分组逻辑测试，覆盖无阶段模型、授权队列、每轮过程折叠与固定耗时、多轮历史恢复、待处理交互、停止及同帧流式同步。
- 文件与长文本回归覆盖精确路径、同名文件、失效绝对路径、相对路径、行列范围、只读文档、完整原文进入模型与持久化恢复；浏览器验证粘贴、展开、移除、复制、多卡片混排、发送与历史预览，并检查暗色正文、图标对齐及 320px 窄屏布局。
- 附件区与浮动授权卡通过浏览器模拟验证：文本卡片在编辑区外、展开编辑、移除、多文本与图片混排、仅附文本发送、授权队列和三种授权响应、进入和退出动画、减少动态效果偏好，以及 280px 窄屏按钮和页面无横向溢出。
- `npm --prefix webview run build`：Vue 类型检查及前端生产构建。
- 手动在 VS Code 开发宿主检查真实模型流、权限点击、滚动与会话切换。本次已使用本地浏览器及模拟扩展事件验证宽屏、390px/280px 窄屏布局、完成后自动收起、耗时冻结、键盘与嵌套工具展开、仅最终答复复制、授权栏和多轮会话恢复，未调用真实模型服务。

全量 `npm run lint` 目前会受到原有 `GitBranchTool.ts` 的 `prefer-const` 和 `ImageGenTool.ts` 的 `no-constant-condition` 两处错误阻断；本次修改的扩展源码通过单独 ESLint 检查。
